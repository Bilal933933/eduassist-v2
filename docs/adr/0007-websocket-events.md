# ADR-0007: اعتماد مقبس الويب لإرسال أحداث الرسم

## الحالة
معتمد

## السياق
تدخل رسائل المستخدم عبر HTTP، وتحتاج الواجهة الأمامية إلى استقبال أحداث تقدم الرسم والنتيجة دون انتظار استجابة الرسالة التقليدية.

## القرار
- تستخدم الواجهة الأمامية مقبس الويب (WebSocket) للأحداث الخارجة فقط.
- تفتح الواجهة اتصال الأحداث قبل إرسال طلب الرسالة عبر HTTP.
- يشغّل مسار الرسالة الرسم عبر البث غير المتزامن (astream_events)، ثم يرسل أحداثًا موحدة ومحدودة إلى الواجهة.
- يُعزل كل اتصال بواسطة معرّف المستخدم ومعرّف المحادثة.
- يبقى سجل الاتصالات داخل الذاكرة في هذه المرحلة ذات الخادم الواحد داخل `realtime/chat_server.py`.
- يسكن مسار الرسائل الرقيق في `api/routes/chat.py`، وتسكن نماذجه في `api/schemas/chat.py`.
- تنسق `services/chat_service.py` تشغيل الرسم وإصدار الأحداث، بينما يسكن مسار مقبس الويب في `realtime/routes.py`.

## البدائل المدروسة
- أحداث مرسلة من الخادم (SSE): مستبعدة في هذه المرحلة لصالح اختيار مقبس الويب.
- إدخال الرسائل وإخراج الأحداث عبر المقبس نفسه: مستبعد لتظل أوامر المستخدم عبر HTTP.

## النتائج
- إيجابيات: قناة واضحة للأحداث واتصال مباشر بالواجهة الأمامية.
- سلبيات: الأحداث غير قابلة للاستعادة بعد انقطاع الاتصال، ولا يعمل السجل بين عدة عمليات خادم.

## خطة الترحيل
عند الحاجة إلى تعدد الخوادم أو استعادة الأحداث، يُوثق قرار جديد لوسيط أحداث دائم قبل تغيير التنفيذ.
