# ADR-0011: قبول المحادثة غير المتزامن وتحديد المعدل

## الحالة
معتمد

## السياق
كان `POST /api/chat` ينتظر اكتمال الرسم كاملًا (استدعاء النموذج) قبل الرد رغم
أن عقده «مقبول» والنتيجة تصل عبر المقبس، فيحتجز اتصال HTTP وجلسة القاعدة طوال
التوليد. وكان `ChatServer` يخزن اتصالًا واحدًا لكل محادثة، فيحذف إغلاق تبويب
اتصال تبويب آخر، ويرمي الإرسال لاتصال غائب `KeyError` بعد حفظ رسالة المستخدم.
ولا حد لمحاولات الدخول ولا لرسائل المحادثة التي تستهلك نموذجًا مدفوعًا. وكان
فحص حالة الحساب قبل كلمة المرور يكشف وجود حساب موقوف، وغياب الحساب أسرع من وجوده.

## القرار
- **قبول ثم تنفيذ:** `accept_chat` يتحقق ويحجز ويحفظ رسالة المستخدم ثم يرد 202.
  `run_chat` يعمل في `BackgroundTasks` بجلسة من مصنع الجلسات، ولا يرمي أبدًا،
  ويحرر الحجز في `finally`.
- **تشغيل واحد لكل محادثة:** `ActiveChatRuns` يرفض الرسالة المتزامنة بـ
  `409 CHAT_BUSY`، مع عمر أقصى 300 ثانية لتفادي حجز عالق.
- **اتصالات متعددة:** يحتفظ `ChatServer` بمجموعة اتصالات لكل محادثة، ويسقط
  الاتصال الميت عند فشل الإرسال، ويتجاهل الإرسال بلا اتصال.
- **تحديد المعدل:** نافذة منزلقة داخل الذاكرة؛ المصادقة بحسب العنوان والمسار،
  والمحادثة بحسب المستخدم. التجاوز يرجع `429 RATE_LIMITED` مع `Retry-After`.
- **الدخول:** تُتحقق كلمة المرور قبل كشف حالة الحساب، والحساب الغائب يستهلك
  تحققًا وهميًا مماثلًا.
- **الإنتاج:** يقبل `ENV` القيم `development | test | production` فقط، وفي
  الإنتاج يفشل البدء عند بيانات DB الافتراضية أو مفتاح Gemini الفارغ أو أصول
  CORS غير https.

## البدائل المدروسة
- طابور مهام دائم (ARQ/Celery): مؤجل لأنه يضيف خدمة ثالثة قبل الحاجة.
- مكتبة محدد معدل خارجية: مستبعدة لأن المحدد الداخلي صغير ومختبر ولا يضيف اعتمادية.
- `asyncio.create_task` مباشرة: مستبعد لأن إدارة دورة حياة المهمة أصعب من `BackgroundTasks`.

## النتائج
- إيجابيات: لا يُحتجز اتصال HTTP ولا جلسة قاعدة أثناء التوليد، ولا يترك فشل
  الإرسال المعالجة معلقة، ولا يسرّب الدخول وجود الحسابات.
- سلبيات: حالة المحدد والاتصالات والتشغيلات النشطة محلية لعملية واحدة، وتشغيل
  عدة عمال يتطلب Redis للعدادات والبث.
- خلف وكيل عكسي يجب تشغيل uvicorn بـ `--proxy-headers` مع `--forwarded-allow-ips`
  وإلا شارك كل المستخدمين عنوان الوكيل نفسه.
- المهمة الخلفية لا تنجو من إعادة تشغيل العملية؛ تبقى رسالة المستخدم محفوظة بلا رد.
